# 主控与规则库兼容性契约

本文档定义 `veydeck`（主控）与 `veydeck-sim-rules`（规则库）之间的接口兼容性约束，规范双方在 Protobuf Schema 演进、版本声明、ID 分区及发版顺序上的协作义务，防止两个独立仓库之间出现单边更新导致的运行时漂移。

> 本文档需要在 `veydeck` 与 `veydeck-sim-rules` 两个仓库中各保留一份。任一仓库修改规则包 Protobuf 结构、归档格式、版本策略或 ID 分区时，必须同步更新另一仓库中的同名文档。

---

## 1. Protobuf Schema 演进规则

主控与规则库各自维护一份 Protobuf 结构定义（Prost Code-first），双方必须在字段名、类型和 `prost(tag)` 编号上保持**逐字段对齐**。

### 1.1 允许的变更

| 变更类型                            | 说明                                                 |
| ----------------------------------- | ---------------------------------------------------- |
| 追加新字段                          | 使用新 tag 编号，不影响旧版解析（Protobuf 向前兼容） |
| 将 `required` 字段放宽为 `optional` | 旧版二进制仍可正常写入                               |

### 1.2 禁止的变更

| 变更类型                | 原因                                                     |
| ----------------------- | -------------------------------------------------------- |
| 删除既有字段            | 对端仍按原 tag 解码，导致数据丢失或反序列化异常          |
| 修改既有字段的 tag 编号 | Protobuf 以 tag 编号为唯一标识，变更后新旧端数据无法对齐 |
| 修改既有字段的类型      | 同 tag 不同类型将导致解码错误或静默截断                  |
| 修改既有字段的语义      | 双方对同一字段的解读出现分歧，产生逻辑漏洞               |

### 1.3 对齐校验

两端的 Protobuf 结构体在以下位置定义：

| 端     | 文件路径                                     | 结构体                                                            |
| ------ | -------------------------------------------- | ----------------------------------------------------------------- |
| 套件 API | `veydeck-suite-protocol-simulation/crates/protocol-simulation/src/rule_package.rs` | `SimRuleProto`、`RuleEndpointProto`、`RulePackageManifestProto`、`SimRulePackageProto` |
| 规则库 | `veydeck-sim-rules/src/lib.rs`                | 同名结构体                                                        |

任何一端修改上述结构体时，**必须同步更新对端的对应定义**，并在 PR 描述中显式标注跨仓库同步关系。

---

## 2. `ruleset_format_version` 语义

`RulePackageManifestProto.ruleset_format_version` 标识规则包的整体格式版本，用于主控在导入时判断自身是否具备对应的解析能力。

### 2.1 格式版本递增条件

当且仅当以下情况发生时，规则库端**必须**递增 `ruleset_format_version`：

- Protobuf schema 发生第 1 节所定义的不兼容变更（即使通过追加新字段绕过了编解码兼容，但新字段的缺失会导致主控逻辑异常时，仍应递增）。
- 规则包的内部归档结构或文件命名约定发生变更。
- `config_json` 内部的 JSON schema 发生不兼容变更（例如移除必填键、修改值类型）。

### 2.2 主控校验义务

套件 API 在导入规则包时，必须同时检查 `schema_version` 与 `ruleset_format_version`。当前只接受 `1`，收到其他版本必须拒绝导入。

### 2.3 v1 端点与签名

- 每条规则必须显式携带具名端点，端点的 transport、container port 和 required 属性必须与 common crate 的协议描述一致。
- DNS 声明 53/TCP 与 53/UDP 双端点，SNMP 声明单个 161/UDP 端点，其他当前协议声明各自标准容器端口的单 TCP 端点。
- `rules.bin.sig` 必须覆盖原始 `rules.bin`，导入端使用可信 Ed25519/minisign 公钥验签。
- 仅存在签名文件、签名编码有效但验证失败、端点缺失或协议行为 schema 不匹配，都必须拒绝整个导入事务。

---

## 3. `min_veydeck_version` 声明义务

`RulePackageManifestProto.min_veydeck_version` 声明该规则库包所要求的最低主控版本号，采用 [SemVer](https://semver.org/) 格式。

### 3.1 规则库端义务

- 每次发版时必须填写 `min_veydeck_version`，不允许留空。
- 当规则库开始使用主控某一版本才引入的新能力（如新增的 Protobuf 字段、新的协议支持、新的 config_json schema 特性）时，必须将 `min_veydeck_version` 提升到对应主控版本。

### 3.2 主控端义务

- 在导入流程中，使用 `semver` 库将主控当前编译版本与 `min_veydeck_version` 进行比对。
- 若主控版本低于声明的最低版本，拒绝导入并返回版本不兼容的错误信息。

---

## 4. ID 分区约束

规则 ID 在主控数据库中全局唯一，需通过分区机制防止包规则与用户自定义规则之间的 ID 冲突。

| 区间              | 归属           | 来源                                       |
| ----------------- | -------------- | ------------------------------------------ |
| `[1, 999_999]`    | 规则库包规则   | 由 `veydeck-sim-rules` 分配并通过规则包导入 |
| `[1_000_000, +∞)` | 用户自定义规则 | 由用户在前端界面手动创建                   |

### 4.1 规则库端约束

- 规则库中所有规则的 ID 必须处于 `[1, 999_999]` 区间。
- MongoDB、Memcached、SNMP、MQTT、VNC 分别使用 `330000–339999`、`340000–349999`、`510000–519999`、`520000–529999`、`640000–649999` 分区。
- 规则库的 CI 审计流程必须包含 ID 分区校验，违规时阻断构建。

### 4.2 主控端约束

- 导入规则包时，逐条校验规则 ID，若发现 ID ≥ `1_000_000` 则拒绝整个导入事务。
- 用户通过 API 创建自定义规则时，ID 必须 ≥ `1_000_000`，若传入 ≤ `999_999` 的 ID 则拒绝创建。
- 包规则不可通过普通删除接口删除，仅在规则库升级中被新包逻辑停用。

---

## 5. 发版顺序约束

当 Protobuf schema 或主控导入逻辑发生变更时，双方必须按以下顺序发布新版本，以保证线上环境的向前兼容性：

```text
1. 主控先行发版：
   └── 新版主控必须同时支持新旧两种 schema 的解析能力
       （旧规则库包在新主控上仍可正常导入）

2. 规则库后续跟进发版：
   └── 新版规则库使用新 schema 打包
   └── min_veydeck_version 指向步骤 1 中发布的主控版本号

3. 过渡期结束后（可选）：
   └── 主控可在后续版本中移除对旧 schema 的兼容支持
   └── 同时递增自身所支持的最低 ruleset_format_version
```

**禁止反向操作**：规则库不得先于主控使用主控尚未支持的新字段或新 schema 发版，否则将导致线上主控无法解析新规则包。

---

## 6. 变更检查清单

开发者在涉及规则库或主控的规则包相关代码变更时，应逐项确认以下检查清单：

- [ ] Protobuf 结构体是否在两端保持 tag、类型和字段名的逐字段对齐？
- [ ] 规则库的 `min_veydeck_version` 是否反映了其所依赖的最低主控能力？
- [ ] 所有包规则 ID 是否处于 `[1, 999_999]` 区间？
- [ ] 若涉及 schema 变更，是否遵循了"主控先行发版"的顺序？
- [ ] PR 描述中是否标注了跨仓库同步关系？

## 规则包归属

协议仿真规则包使用 `.vprp` 后缀（Veydeck Protocol Rule Package）。manifest 必须包含 `suite_id = "veydeck.protocol-simulation"`（Protobuf tag 8）和 `package_type = "protocol-simulation-rules"`（tag 9）。两字段随 `rules.bin` 一起签名；导入端拒绝缺失或不匹配的归属。
